# /open — Открытие дня (облегчённый ОРЗ, INV-9)

Роль: ассистент в личном vault. Тон инженерный (INV-16).

> Распорядок (окно слота, ёмкость будня и выходного, день стратегирования, часовой пояс) скилл **читает из `80-kernel/config.md`** («Ритм», «Календари»), а не держит в себе: конфиг есть источник истины о распорядке. Поменялся уклад — правится конфиг, скилл не трогается.

0. `bash 80-kernel/scripts/orz-check.sh` — строка `📍` (положение в спринте и юните, ADR-0037) плюс флаги пропуска ритма (незакрытый день / нет UnitPlan / нет SprintPlan). Есть флаг → разобрать до планирования (закрыть вчера / `/strategize`). Тот же детектор на SessionStart-хуке (INV-5/INV-10).
1. `date`. Сверить с **ритмом** (`80-kernel/config.md` секция «Ритм»): сегодня будний/выходной; день стратегирования (`strategy_day`)? Если да — где в дне встаёт `/strategize` и какой у него бюджет по режиму (45–180 мин). **Выходной → напоминание** о том, что «Ритм» говорит про утро выходного: если утренний слот объявлен защищённым в любой день недели, календарный выходной его не отменяет.
2. **Утвердить план работ на сегодня.** Прочитать последний `10-governance/8-sessions/*.md` — секцию «План работ на завтра», свёрстанную вчерашним `/close`. **Предъявить её владельцу и дождаться утверждения** — это единственный шаг открытия, где решение принимается им, а не выводится из данных.

   Вчерашний план есть **предложение, а не наряд**: ночь и утро меняют вход (самочувствие, сдвинутый календарь, прилетевшее срочное). Спросить прямо: идём как записано, меняем состав, меняем порядок? Утверждённый состав ложится в DayPlan шагом 6; отклонённые работы возвращаются в пул юнита, не пропадая.

   Секции нет (день не закрывался) — сказать об этом и собрать план из пула юнита здесь же, отметив, что вчерашнее закрытие пропущено.
2.5. ⛔ **Инбокса на открытии дня НЕ касаться.** Разбор инбокса принадлежит стратегированию и только ему — `80-kernel/docs/inbox-triage.md` читает `/strategize`, не этот скилл. Ежедневный триаж «в режиме light» на деле означает ежедневное предъявление владельцу нерешённых строк, то есть перенос его же решений в день, где им не место. Класть **в** инбокс по ходу дня по-прежнему можно и нужно; доставать из него — нет.
3. Активные задачи: `10-governance/6-tasks/` где `status` ∈ {in-progress, blocked} **и `awaiting` пуст либо уже наступил**. Карточка с датой в будущем в список дня не идёт и работ на неё не верстается: петля открыта, но следующий шаг наступает по календарю (`task-discipline.md` § «Открытость петли ≠ требование внимания»). Вернёт её сам `orz-check` в назначенный день. Показать **остаток** по каждой (`budget_h` минус `spent_h`), а не номинал — он и есть вход выбора на день.
4. **Слот — первым** (окно из config «Ритм»): окно на **важные задачи инвестиционных проектов** (`investment: true` в карточке; проекты спринта — из действующего SprintPlan) из пула юнита — одна или две, если помещаются. Срочное слот не вытесняет. Детали источника обучения (прогресс, расписание) — в карточке `20-library/resources/**` (ADR-0020).
5. **Календарь** — список календарей и роли из `80-kernel/config.md` (секция «Календари»). MCP календаря `list_events` на сегодня (`timeZone` — часовой пояс из config, окно 00:00–23:59) по каждому календарю с ролью **busy**/**slot** (`calendarId` из конфига); **info** — справочно, **ignore** — пропустить. Свести занятые блоки и **свободные окна ≥1ч**; отметить конфликты с утренним слотом / 🔴 работами; связать релевантные события с задачами. Событий нет — строкой «календарь пуст», секцию в DayPlan не разворачивать (INV-3). MCP недоступен/не отвечает или календари не настроены — пропустить шаг, не блокировать открытие.
6. Написать DayPlan → `10-governance/7-plans/current/dayplan-YYYY-MM-DD.md` из скелета `80-kernel/scaffolds/dayplan-tmpl.md`: слот + 2–3 работы + фокус дня. Лёгкий. **Ёмкость** — по config «Ритм»: сколько своего времени у будня и у выходного, что из дня занято наймом (его план живёт в рабочем контуре и в DayPlan не верстается), где только крошки времени (решения, постановка агентам, чтение) — работ юнита на них не верстать. Не перегружать день сверх реального окна. Работы дня — таблицей со **светофором-приоритетом** (колонка `🚦`, легенда в скелете): светофор = приоритет, НЕ статус (статус живёт в карточке задачи). «Результат» в DayPlan не носим — итоги в session log (INV-3).
6.5. **Зеркало утверждённых работ в приборе** — *если прибор учёта подключён (Super Productivity MCP, ADR-0029)*. `update_task` с `due_day: YYYY-MM-DD` по задачам, которые владелец взял в план на шаге 2. ⚠️ **Не `plan_tasks_for_today`:** он ставит только `plannedAt` (планировщик), а список «Сегодня» наполняется полем `due_day` — задача в день не попадает, а инструмент возвращает `success`. Задачи прибора ищутся по префиксу `T-NNN` в заголовке; взятые в план кладутся в Today, прочие не трогаются.

   Без этого шага помидор пишется на задачу, которой в списке дня нет, — и либо заводится вторая запись, либо время уходит на ведро. Прибор есть носитель учёта работы ([[ADR-0031-project-mirrored-in-time-tracker|ADR-0031]]), и день, открытый в vault, обязан быть открыт и в нём: иначе `spent_h` на `/close` снимать неоткуда.

   Зеркала нет вовсе (задача заведена только в vault) — сказать об этом строкой, задачу в приборе **не создавать молча**: номер назначает реестр, и заведение зеркала есть отдельное действие владельца.

   ⛔ **Готовность в приборе не ставится агентом никогда**: в Today кладу я, выполненной отмечает владелец. Снять `timeSpent` для `/close` можно и с незакрытой задачи — чтение готовности не требует.

7. Создать `10-governance/8-sessions/YYYY-MM-DD.md` из скелета `80-kernel/scaffolds/session-tmpl.md` (пустой журнал, наполняется по ходу).
8. commit (+ push, если ваш vault пушится без подтверждения); *опционально* — в коммит и `10-governance/7-plans/current/week-time.md`, если его обновил запуск `80-kernel/scripts/week-time.py` по расписанию (механизм запуска — на ваш выбор): файл пишется часто, а в git попадает только с ритуалом.

Не делать: 4-местную регистрацию задач, агрегацию по чужим репо, тяжёлую субагент-верификацию. Это личный vault, не платформа.
