Оцени решение: $ARGUMENTS

## Шаг 0. Принципы (ДО оценки)

Сверь решение с инвариантами `80-kernel/stele/contract.md` и лестницей принципов (`.principles` ZP→FPF→SPF, через `/fpf`). Нарушает инвариант/принцип — сообщи и предложи исправление до оценки.

## Шаг 1. Два вопроса пользователю (БЛОКИРУЮЩЕЕ)

> **СТОП. Не переходи к шагу 2 без ответа на ОБА вопроса.** Не угадывай за пользователя.

**Вопрос 1:** «Какие 1–2 характеристики критичны для этого решения?» (напр.: хранилище секретов → Безопасность; вложенный репозиторий/MCP → Эволюционируемость + Современность). ❌ в критической = немедленный СТОП.

**Вопрос 2 (A.19 Lawful Comparison):** «Какие альтернативы рассматривались?»

- ≥2 варианта → сравнительная таблица (шаг 2б).
- «нет / только этот» → оценивай, но в вердикте пометь: *«Оценка без сравнения — уверенность ниже.»*

Задай оба одним сообщением. Дождись ответа. Только потом — шаг 2.

### 2б. Сравнительный режим (≥2 вариантов)

Сводная таблица: строки — 7 характеристик, колонки — варианты (✅/⚠️/❌) + строка «Вердикт». Рекомендуемый — наименьшее число ⚠️ при отсутствии ❌ в критических.

## Шаг 3. Вето-фильтр (conjunctive screening)

> Non-compensatory: высокий статус по одной характеристике НЕ компенсирует блокер по другой. Проверь каждое правило явно.

**Правило 1. Критические.** Перечисли критические из шага 1 + их статус. Любая критическая = ❌ → сработало.

**Правило 2. Число блокеров.** Перечисли все ❌. N≥2 → сработало.

**Правило 3. Соотношение ⚠️/✅.** Перечисли все ⚠️ и ✅. ≥4⚠️ и 0✅ → сработало.

**Вердикт:**

- Хотя бы одно сработало → **СТОП.** «Решение НЕ проходит АрхГейт. Блокеры: [список]. Рекомендация: [что исправить].» → шаг 4 (обратная связь по принципам), завершай.
- Ни одно → **проходит вето** → шаг 4.

## Шаг 4. Обратная связь и выход

**Проходит:** «Решение проходит АрхГейт.»

Для каждой ⚠️ — запроси явное решение: «[Характеристика] ⚠️. (а) принимаю риск — [обоснование]; (б) митигация — [что конкретно].»

Для ⚠️/❌ — обратная связь по принципам: принцип есть и решение противоречит → пересмотреть; принцип слаб → усилить; принципа нет → предложить (инвариант контракта или новый ADR).

**Выход — ADR (БЛОКИРУЮЩЕЕ для значимых решений):** прошедшее значимое решение фиксируется как ADR с профилем ЭМОГССБ в секции «Альтернативы/Последствия» (как ADR-0001/0002). **Дом ADR зависит от системы (ADR-0023):** решение о самом ядре vault (SYS-000) → kernel-Стела `80-kernel/stele/ADR-NNNN-slug.md` (шаблон `80-kernel/scaffolds/adr-tmpl.md`); решение о развиваемой внешней системе (SYS-NNN, напр. `<system-name>`) → **приватно** `10-governance/9-systems/SYS-NNN/adr/NNNN-slug.md`, **НЕ** в её (часто публичный) репо. Тривиальное/обратимое — без ADR.
