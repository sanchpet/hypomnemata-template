# /fpf — Загрузка принципов

Запрос: $ARGUMENTS

## Лестница принципов (две оси)

- **Контракт (нисходящий — обоснование):** `ZP → FPF → SPF → паспорта (30-knowledge)`. Верхний уровень ограничивает нижний; так знание создаётся/валидируется (режимы design, passport, review идут сверху вниз).
- **Резолюция (восходящий — fallback):** `локальная Стела/паспорт → SPF → FPF → ZP`. Поиск начинай со специфичного применимого слоя, откатывайся вверх (режимы lookup, diagnose).

Источники: вложенные репозитории `.principles/{zp,fpf,spf}` (прямой Grep/Read, офлайн; разворачивает `repos-bootstrap.sh`, ADR-0038) — **основной и достаточный**. Карта и перевод терминов — `.principles/README.md`.

> **Опционально — MCP `mim-knowledge`** (семантический поиск по корпусу МИМ/FPF/SPF). Нужна учётная запись платформы МИМ и подключение в `.mcp.json`. Без него скилл работает полностью — шаг 3 алгоритма просто пропускается.

## Режимы (определи по запросу)

| Режим | Триггер | Что делать |
|-------|---------|-----------|
| **lookup** | Код паттерна (A.7, B.5, ZP.2) или конкретный термин | Grep по нужному вложенному репозиторию → точная секция → объясни в инженерном языке |
| **review** | «проверь», «сверь с FPF/SPF», артефакт на проверку | Загрузи артефакт + релевантные принципы → сверка пункт за пунктом → findings |
| **design** | «спроектируй», «как по FPF», задача проектирования | Подбери применимые паттерны (границы A.1, состав A.6, различения A.7, ADI B.5) → рекомендации |
| **characterize** | «сравни», «оцени варианты», «как выбрать» | A.17-A.19 Lawful Comparison: критерии → индикаторы → оценка по одной шкале |
| **teach** | «объясни FPF/SPF/ZP», «что это», «введение» | Обзор фреймворка: что, зачем, ключевые блоки → инженерный язык без жаргона |
| **diagnose** | «какие принципы нарушаю», «что не так», «найди проблему» | Описание работы → расхождения с принципами → конкретные нарушения (принцип + где) |
| **prioritize** | «наиболее важны», «для роли», «как X» | Роль из аргумента → релевантные принципы → ранжируй → почему важны для роли |
| **passport** | «паспорт домена», «формализовать предметную область» | → запусти `/domain` (полный guided-flow создания паспорта по SPF). `/fpf` сам паспорт не создаёт (OwnerIntegrity). |

**БЛОКИРУЮЩЕЕ — No-Jargon (INV-6):** каждый термин фреймворка в выводе → инженерный эквивалент (в скобках или вместо). Таблица — `.principles/README.md` § перевод. Неизвестный термин: перевести по контексту + `(FPF: <оригинал>)`. Тест перед выводом: есть ли термин, непонятный инженеру без фреймворка? Да → перевести.

## Алгоритм

1. **Определи режим** по таблице. Неясно → lookup.
2. **Классифицируй слой источника:**
   - домен/предметная область, паспорт → SPF (+ локальные `30-knowledge/`)
   - базовые различения, состав, роли, первые принципы → FPF
   - транс-дисциплинарные ограничения (причинность, инварианты, масштаб) → ZP
   - архитектура/правила этого vault → локальная Стела `80-kernel/stele/`
3. **Семантический поиск через MCP** — только если `mim-knowledge` подключён (виден в `/mcp`):
   - `knowledge_search(query="<запрос>")` → найти релевантные секции/концепты
   - `knowledge_get_document(...)` → полный текст; `personal_search` → свои материалы МИМ
4. **Точное место — в локальном вложенном репозитории** (всегда, даже после MCP):
   - FPF: `Grep` по `.principles/fpf/FPF-Spec.md` (обзор — `Readme.md`)
   - SPF: `.principles/spf/spec/` `docs/` `ontology.md`
   - ZP: `.principles/zp/principles/ZP.N-*.md` (карта — `hierarchy.md`)
5. **MCP недоступен или не подключён** → шаг 4 как единственный источник (Grep/Read по `.principles/`).
6. **Покажи** принципы с привязкой к задаче + ссылку на источник (файл/секция). **Переводи термины** в инженерный язык.

## Обновление источников

`bash 80-kernel/scripts/repos-bootstrap.sh pull` (pull-by-need; каталога нет — `clone`). Принципы — чужой апстрим, тянуть их можно без отдельного решения.
