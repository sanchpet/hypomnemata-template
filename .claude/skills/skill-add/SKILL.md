# /skill-add — затащить чужой скилл или плагин

Источник: $ARGUMENTS

Чужой скилл — это **чужой код в твоём агенте**, исполняемый с твоими правами и твоим контекстом. Порядок ниже про две вещи: не установить лишнего и не завести копию, которую потом обновлять руками.

> Это **тонкий** скилл: классификация источника + выбор дома + команды. Про изменение окружения вообще — ваш механизм dotfiles; про оценку архрешения — `/archgate`.

## Шаг 1. Классифицировать источник

Смотреть в дерево репо **до** клона: `gh api 'repos/<owner>/<repo>/git/trees/HEAD?recursive=1' --jq '.tree[].path'` (кавычки обязательны — `?` съест zsh).

| Что видно в дереве | Что это | Как ставится |
|--------------------|---------|--------------|
| `.claude-plugin/marketplace.json` | **маркетплейс** (может нести несколько плагинов) | `claude plugin marketplace add <owner>/<repo>` → `install` |
| `.claude-plugin/plugin.json` без marketplace | плагин внутри чужого маркетплейса | `claude plugin install <plugin>@<marketplace>` |
| только `SKILL.md` (голый скилл) | **нет апстрим-канала обновления** | см. шаг 4, вариант «голый скилл» |

## Шаг 2. Разведка — прочитать до установки (БЛОКИРУЮЩЕЕ)

Читать через `gh api repos/<owner>/<repo>/contents/<path> --jq .content | base64 -d`, не клонируя.

1. **`description` во frontmatter — это триггер-поверхность.** Скилл model-invoked: он включается сам, когда контекст подходит под описание. Разговорные фразы в `Use when` означают, что режим может встать без твоей команды. Проговори владельцу фактические триггеры, а не заявленные в README.
2. **Инструкции на самозакрепление** — «активен каждый ответ», «сомневаешься — активен», условия выключения. Такой скилл переживает свою задачу и конкурирует с конвенциями из `CLAUDE.md`.
3. **Хуки, MCP-сервера, агенты, `allowed-tools`** в манифесте — исполняемая поверхность. Хук выполняется без твоего решения; MCP-сервер поднимает процесс и ходит в сеть.
4. **Запрос кредов / чтение вне репо / сеть** в теле скилла.
5. **Лицензия и автор.**

**Вето (ставить только через `/archgate` и с явным решением владельца):** хуки, MCP-сервера, любой доступ к секретам, отсутствие лицензии.

## Шаг 3. Выбрать дом

Вопрос не «куда положить копию», а «нужна ли копия вообще». По умолчанию — не нужна.

| Дом | Когда | Обновление |
|-----|-------|------------|
| **нативно, `--scope user`** (default) | тест, личное использование, всё чужое | `claude plugin update` — pull апстрима |
| **нативно, `--scope project`** | нужен всей команде конкретного репо, декларируется в его settings | то же |
| **dotfiles** (напр. chezmoi external) | нужна воспроизводимость на другой машине | применение dotfiles |
| **вендоринг в `.claude/skills/` vault** | **почти никогда для чужого** | руками, навсегда |

Вендоринг чужого скилла в vault оправдан ровно в одном случае: он становится **глаголом самой системы** (как `/open`, `/task-new`) и ты принимаешь авторство. Иначе это форк без апстрима — балласт по INV-3 и размытая writer-ownership (INV-19).

**Скоуп по смыслу, не по удобству:** скилл про предметку vault — в vault; скилл про окружение и тон — user-level, он нужен во всех репо, а не только там, где стоит.

## Шаг 4. Поставить

```sh
claude plugin marketplace add <owner>/<repo>     # --scope user|project|local
claude plugin install <plugin>@<marketplace>     # --scope user (default)
```

**Голый скилл (без манифеста):** апстрим-канала нет. Либо форкнуть себе и тянуть из форка (`git remote add upstream`, обновление осознанным мержем), либо положить в `~/.claude/skills/<name>/` и принять, что апдейт ручной. Скаффолд пустого своего: `claude plugin init <name>`. Выбор проговорить владельцу, не решать молча.

## Шаг 5. Проверить и разграничить контуры

- **Состояние плагинов лежит в `$CLAUDE_CONFIG_DIR`, если он задан, а не в `~/.claude`.** Проверить переменную (`echo $CLAUDE_CONFIG_DIR`) **прежде** чем идти в файловую систему. Если профили разведены (например, личный и рабочий — разными значениями `CLAUDE_CONFIG_DIR`), пустой `~/.claude/plugins/` при успешной установке читается как «установка не сработала», хотя она сработала — не спутать.
- **Верифицировать состоянием, а не файлами:** `claude plugin list` (статус, версия, scope) и `claude plugin marketplace list`. Команда знает, где её состояние; догадка о путях — нет.
- `claude plugin details <name>` — **инвентарь компонентов и стоимость в токенах**: `always-on` платится каждой сессией, `on-invoke` — каждой активацией. Назвать владельцу обе цифры.
- Плагин подхватывается **со следующей сессии**, не в текущей. Нужен эффект сразу — прочитать `SKILL.md` и его `references/` напрямую из каталога маркетплейса и применить вручную; слэш-команд плагина при этом всё равно нет, о чём сказать владельцу.
- **Контуры, разведённые целым профилем, изолированы без отдельной настройки.** `CLAUDE_CONFIG_DIR` переносит весь каталог — settings, креды, MCP, плагины. Поэтому `--scope user`, поставленный из одного профиля, в другом **не виден вообще**: изоляция уже есть, отдельного запрета не требуется. Обратная сторона: то, что нужно в обоих контурах, ставится дважды.
- **Установка ≠ включённость:** `claude plugin disable|enable <name>` — держать поставленным и выключенным законно.

## Шаг 6. Обновление и откат

```sh
claude plugin marketplace update [name]   # без имени — все маркетплейсы
claude plugin update <plugin>             # требует рестарта сессии
claude plugin uninstall <plugin>
claude plugin marketplace remove <name>
```

Автообновления нет — это ручной жест. Обратной стороной: ничего не меняется у тебя за спиной.

## Шаг 7. Зафиксировать

Ставили нативно и на пробу — фиксировать нечего, откат в одну команду.

Решение оставить (особенно с вето-признаками из шага 2, со сменой дома или с правкой `settings.json`) — это уже архрешение: `/archgate`, при прохождении ADR в `80-kernel/stele/`. Свой скилл заводится или меняется — обновить каталог `80-kernel/docs/skills.md` (обзор, не дубль логики).
