# /task-new — завести задачу

Новая задача: $ARGUMENTS

> Метод — `80-kernel/docs/task-discipline.md` (источник, здесь не дублируется). Задача = ОДНА self-contained карточка (ADR-0013, ADR-0036); реестр и доску собирает Dataview (`index`). Никакой записи в несколько мест — это был балласт апстрим-шаблона IWE, от которого система отталкивалась (OwnerIntegrity).

## Шаг 0. Проверка рода (БЛОКИРУЮЩЕЕ — до создания)

1. **Это действие внутри проекта?** Задача продвигает проект к выполнению. Порога по длительности нет — он снят ADR-0036 вместе с понятием РП как единицы планирования; величина рода не меняет.
2. **Задача ≠ проект.** Результат размытый, охватывает много разных выходов → это конечный проект (`scope: finite`) из нескольких задач → предложить декомпозицию.
3. **Задача ≠ процесс.** «Отслушал / разобрался / поработал» — деятельность, после которой в мире ничего не осталось. Спроси: «что изменится в мире, когда работа сделана?»
4. **Заслуживает ли действие карточки** — лестница четырёх вопросов (`task-discipline.md`, § «Куда селится действие, которому карточка не полагается»): вне проекта → ведро «Разное»; повторяется без конца → повтор в приборе; само по себе проект не двигает → строка чек-листа внутри задачи покрупнее. Карточка — всё остальное.
5. **Трассировка:** назван ли проект? Родитель у задачи один (ADR-0035). Задача юнита берётся только в проект с `criterion` (проект и есть цель, ADR-0040) — если критерия у проекта нет, это повод остановиться и спросить владельца, а не завести задачу молча.

Задача объективно нужна → **предложить формулировку и дождаться «да»**. Имя = действие с названным предметом («Заполнить таблицу критериев выбора»), не размытое существительное.

## Шаг 1. Номер

Найти максимальный `T-NNN` в `10-governance/6-tasks/` (включая `archive/` и `backlog.md`) → +1. Только целые, без буквенных суффиксов. Гейт `task-id-unique` ловит коллизию параллельных сессий на коммите.

## Шаг 2. Карточка

Скопировать `80-kernel/scaffolds/task-tmpl.md` → `10-governance/6-tasks/T-NNN-<slug>.md`. Заполнить frontmatter: `id`, `project` (единственный родитель), **`role`**, **`method`** и **`importance`** (назначаются здесь, чтобы планировщик их не искал; важное ≡ инвестированное — растёт метод или появляется новая работа, текущее — меняется вещь), `budget_h`, `status`, `verification_class`, `opened`.

**`artifact` — рабочий продукт.** При заведении желателен: если ясность есть, называй сразу. Обязателен он с момента, когда задача берётся в юнит (поле `unit:`) — там гейт `task-artifact` начинает краснеть. Рабочий продукт есть **изменение в мире**, не обязательно документ: у «позвонить и записаться на приём» это назначенная явка.

Тело — self-contained: постановка, метод, раздел «Работы» (пока пуст — формулировки появляются на планировании), критерий done.

## Шаг 3. В прибор — только работы (ADR-0036)

> *Шаг для тех, кто ведёт прибор учёта Super Productivity с MCP (ADR-0029). Без прибора — пропустить: карточка самодостаточна.*

**Задача сама в приборе не заводится.** Граница: в моделере стратегическое, в приборе — сформулированные работы. Пока задача не взята в юнит, в приборе её нет и быть не должно.

Когда задача берётся в юнит, на каждую сформулированную работу — `mcp__super-productivity__create_task`:

- `title` — **`T-NNN — <формулировка работы>`**; префикс несущий, по нему детектор находит работы задачи. Номер с ведущими нулями (`T-007`).
- `project_id` — проект-зеркало из поля `project:` карточки (ADR-0031, 1:1 с реестром; список — `get_projects`).
- `time_estimate` — бюджет работы в **миллисекундах** (1 ч = 3600000); сумма работ сходится с `budget_h` карточки.
- `tag_ids: ["<invested-tag-id>"]` (`Инвестированное`) — если работа идёт в инвестированное время, а не в рабочую текучку.
- `tag_ids` классификации (ADR-0036): **`<important-tag-id>`** (`Важное`) — работе отдаётся приоритет в дне; **`<urgent-tag-id>`** (`Срочное`) — вошла внутри периода и не успевает на очередное планирование. Отсутствие тега значит противоположный полюс, поэтому ставить их надо при заведении, а не потом. Ось «Постоянное / Временное» тега не имеет — её несёт конфигурация повтора.

Id тегов — свои у каждой установки прибора: заведите теги один раз (`create_tag`), узнайте id (`get_tags`) и запишите их в `80-kernel/config.md` (секция «Прибор учёта»: `sp_invested_tag`, `sp_important_tag`, `sp_urgent_tag`), откуда их и брать.

Работ у задачи может быть несколько — кратность 1:N. Id задачи прибора **в карточку не писать**: обратная запись в файл, за которым следит хук `task-mirror-remind`, дала бы петлю.

## Шаг 4. Подтверждение

«Задача T-NNN заведена: <имя>. Роль: <…>. Метод: <…>. Бюджет: <…> ч. Рабочий продукт: <… либо «назовём при взятии в юнит»>. Класс верификации: <…>. Доска (`index`) подхватит.» Связи — через wikilinks, Dataview агрегирует сам.
