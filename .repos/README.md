# `.repos/` — mount-точка клонов кода

> **Корень раскладки клонов объявляет машина ([[ADR-0030-repos-root-per-machine|ADR-0030]]).** Пустой каталог — не поломка: значит, на этой машине клоны живут вне vault'а, под `<repos-root>`. Путь спрашиваем у инструмента, который владеет машинно-локальной конфигурацией (менеджер dotfiles, `git config --get-regexp includeif` для рабочего корня), а не читаем отсюда.

Dot-зона: видна агенту и редактору, Obsidian её игнорирует (ADR-0002). Сами репозитории внешние, со своими remote, и в git vault'а не входят (`.gitignore: .repos/*`); трекается только этот README.

**Раскладка по источнику (ADR-0022):** поддерево на источник — например, `github/` для личного и `<employer>/` для рабочего. Принцип от корня не зависит: где бы корень ни лежал, источники разведены по поддеревьям.

**Реестр клонов** — по желанию: `CLAUDE.md` в поддереве источника (`.repos/<source>/CLAUDE.md`) с таблицей «каталог · remote · конвенции». Агент подхватывает его по cwd. Чтобы трекать его в vault, допишите `!.repos/<source>/` и `.repos/<source>/*` с `!.repos/<source>/CLAUDE.md` в `.gitignore`. Если корень клонов вне vault'а, примонтируйте реестр симлинком, иначе по cwd он не подхватится:

```
ln -s <vault-root>/.repos/<source>/CLAUDE.md <repos-root>/CLAUDE.md
```

Вложенные репозитории самого vault'а (принципы `.principles/`, опциональное ядро знаний) живут не здесь, а в исполняемом реестре `80-kernel/scripts/repos-bootstrap.sh` (ADR-0038).
