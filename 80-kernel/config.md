# Конфиг установки

> Параметры установки системы под конкретного инженера — то, что скиллы и детекторы читают детерминированно (не выводится из кода/состояния).
> Один файл, секциями. Дробить по отдельным файлам — когда второй скилл-потребитель захочет свой срез **И** файл вырастет настолько, что чтение целиком стоит контекста. Пока файл мал — один файл (напр. «Ритм» читают и `/open`, и `/strategize`, но цена чтения целиком пренебрежима). До тех пор `config/`-каталог = балласт (INV-3). Решение — [[ADR-0018-installation-config|ADR-0018]].

> **Шаблон.** Значения в угловых скобках — ваши; заполните их до первого `/open`. Строки вида `ключ: значение` читаются скриптами грепом — меняйте значение, а не форму строки.

## Календари (Google Calendar MCP, опционально)

> Читает `/open` при поиске свободных окон дня. Роль определяет трактовку:
> - **busy** — события занимают время, блокируют слоты.
> - **slot** — busy + релевантно слоту саморазвития (лекции, учёба).
> - **info** — показывать справочно, НЕ блокировать окна.
> - **ignore** — не читать.
>
> `/open` запрашивает `list_events` по каждому календарю с ролью **busy**/**slot**; **info** — справочно; **ignore** — пропускает. `calendarId` = значение из колонки id. Нет MCP календаря — `/open` пропускает шаг, не блокируя открытие.

| Календарь | Роль | id |
| --- | --- | --- |
| `<саморазвитие>` | slot | `<calendar-id>` |
| `<работа>` | busy | `<calendar-id>` |
| `<встречи с людьми>` | busy | `<calendar-id>` |
| `<primary>` | busy | `<calendar-id>` |
| `<дни рождения>` | info | `<calendar-id>` |

Id календаря без OAuth доступа не даёт, но в публичный репозиторий его всё равно не кладут: это идентификатор, по которому вас находят.

### Календарь держит обещания другим людям, ритм — нет

В календаре живут события с чужим расписанием и обещания людям (семинары, встречи). Повторяющиеся серии собственного ритма (тренировки, слоты, дорога) туда не заводятся: их описания отстают от конфига и стреляют отменёнными правилами из копий. Распорядок живёт только здесь, в «Ритме», и в DayPlan.

### Событие — в профильный календарь, а не в primary

`primary` — не свалка для всего личного: положенное туда событие выпадает из фильтра, которым владелец смотрит контур. Календарь назначать **до** создания события; MCP не умеет переносить событие между календарями — перенос делается созданием в целевом и удалением исходного.

### Зона события — едет ли оно вместе с владельцем

Личные практики (тренировка, слот, ритуалы ОРЗ) привязываются к **зоне проживания** (`timezone` ниже). Внешние обязательства с чужим расписанием остаются в зоне организатора: их час назначен не владельцем.

Различитель: **едет ли событие вместе с владельцем**. Утренняя тренировка едет — она в тот же час везде, где он проснулся. Вебинар организатора стоит — он идёт, когда идёт.

**Почему:** при смене часового пояса проживания вспомогательные календари остаются в прежней зоне, и каждая личная практика молча уезжает на разницу поясов. Прибор, которым меряют исполнение программы, показывает не то время, в которое программа исполняется. **При переезде пройти этот раздел заново.**

### Напоминания — умолчание живёт на календаре, а не на событии

Умолчание напоминаний задаётся календарю и стреляет по каждому его событию — в том числе в окно сна, если напоминание за несколько часов. Личные практики получают `overrideReminders` на событии, иначе умолчание календаря стреляет из-за угла.

### Правка времени через MCP — расщеплённая серия и эхо смещения

- Правка времени у мастера повторяющегося события через MCP работает; `RRULE` переживает. **Исключение — расщеплённая серия** (id с суффиксом вида `…_RYYYYMMDDTHHMMSS`, след правки «это и последующие»): перенос её начала API отвергает (`invalid argument`) в любой форме. Лечится ручным перетаскиванием в UI либо удалением серии и созданием заново через `recurrenceData` (второе стирает прошлые вхождения).
- Ответ API эхом отдаёт смещение календаря по умолчанию, даже когда зона события уже другая. **Проверять не эхо записи, а `list_events` с `timeZone` — по экземплярам.**
- Зона самого календаря меняется только в настройках Google, не через MCP.

## Ритм

> Параметры ритма ОРЗ. Читает `/open` (вёрстка DayPlan под реальную ёмкость), `/close` (раскладка завтрашнего дня), единый ритуал `/strategize` и детектор `80-kernel/scripts/orz-check.sh` ([[ADR-0037-sprint-unit-planning-frame|ADR-0037]]).

> **Конфиг есть источник истины о распорядке**; календарь — побочный продукт планирования для удобства. **Смена уклада обязывает две правки в тот же день, а не одну:** (1) настоящую секцию — иначе скилл верстает день по отменённому распорядку; (2) действующий UnitPlan и DayPlan, строка за строкой — план верстается под геометрию дня, и смена геометрии обнуляет назначения, адресованные окнам, которых больше нет. Урок автора: дефект повторялся с переменой носителя (истина жила то в описаниях событий календаря, то в журнале сессии), класс один — **геометрия записана там, где её удобно написать, а не там, где её читают.**

### Зона проживания

- **timezone: `<Area/City>`** — IANA-зона, в которой живут личные практики и считается день. Читают `/open` (окно `list_events`) и учёт времени.

### День стратегирования

- **strategy_day: суббота.** На него опираются `orz-check.sh` (look-ahead недельных ветвей) и `/strategize`. Запуск off-day допустим как осознанное исключение.
- Значение — день недели по-русски, и в строке параметра он должен быть единственным названием дня: детектор матчит подстроку первой такой строки, а нераспознанное значение откатывает на первый день недели. У автора — суббота; поставьте свой.
- Довод автора за субботу: свежее свидетельство (рабочая неделя кончилась накануне), холодная голова и вход в понедельник по уже написанному плану. **Time-box ≤2 ч** — ритуал не должен разворачиваться в рабочий день.
- **Неделя остаётся ISO (пн–вс)** — нумерация файлов `YYYY-wNN`, dataview и детектор не трогаются. Сессия верстает **вперёд**: открытие юнита ставит две следующие ISO-недели, открытие спринта — двенадцать.
- **Один ритуал, не очередь.** Смежные процедуры дня стратегирования (триаж репо-эстейта — `80-kernel/docs/repo-triage.md`) поглощены шагом `/strategize`: отдельная процедура после сессии копит долг. Порядок — сессия задаёт приоритеты, триаж разгребает эстейт под них.

### Спринт и юнит — точка отсчёта

- **sprint_epoch: `<YYYY-Www>`** — ISO-неделя начала первого спринта (год, `-W`, номер недели). Пример значения не пишется в этой строке: детектор берёт первую пару «год-неделя», какая в ней найдётся. Единственная точка, от которой считаются все границы: спринт есть 12 ISO-недель, за ним разгрузочная, период цикла 13 недель. `orz-check.sh` **читает этот параметр**, а не вычисляет эпоху сам. Пока значение не задано, ветки рамки (спринт, юнит, режим) молчат, а детектор поднимает об этом флаг.
- 🔴 **Параметр обязан читаться, а не дублироваться в коде.** У автора прежний параметр детектор не читал вовсе — вычислял дату арифметикой, — и потому правка конфига ничего не меняла, а пропуск ритуала был бесшумен пять недель.
- **Имя спринта** — `YYYY-sN`, где `N = (первая ISO-неделя − 1) / 13 + 1`. **Имя юнита** — `YYYY-wNN-wMM` по его двум неделям. Календарь спринтов на год выпишите здесь, когда зададите эпоху: `<YYYY-sN> = W..–W.. · разгрузочная W..`.

### Режимы дня стратегирования

> Один ритуал `/strategize`; режим **вычисляется** из `sprint_epoch` и наличия артефактов, печатается первой строкой и подтверждается владельцем ([[ADR-0037-sprint-unit-planning-frame|ADR-0037]]).

| День стратегирования | Режим | Бюджет |
|---|---|---|
| нечётная неделя юнита | сверка остатка | 45 мин |
| чётная неделя юнита | закрытие юнита + открытие следующего | 90 мин |
| последняя неделя спринта | закрытие спринта | 135 мин |
| разгрузочная неделя | открытие спринта (+ цели года в первую разгрузочную года) | до 180 мин |

- **Разгрузочная неделя** — род периода, а не пауза: работы меньше, досуга больше, размышление о следующем спринте есть её содержание.
- ⛔ **Закрытие месяца и квартала сняты** вместе с масштабами ([[ADR-0037-sprint-unit-planning-frame|ADR-0037]]): месяц не кратен неделе, квартал начинается посреди недели, и пропуск обоих был недетектируем по построению.

### Будни

> Скелет. Заполните таблицу своим укладом; `/open` верстает день по ней, а не по календарю.

| Время | Блок | Что |
|---|---|---|
| `<HH:MM–HH:MM>` | утро | `/open` |
| `<HH:MM–HH:MM>` | 🎯 **слот** саморазвития | важные задачи инвестиционных проектов (`investment: true`); почта и чат не открываются до конца слота |
| `<HH:MM–HH:MM>` | 💼 роль | работа по найму; её план живёт в рабочем контуре и в DayPlan не верстается |
| `<HH:MM>` | вечер | `/close` — итоги дня и раскладка завтрашнего |

- **slot: `<HH:MM>–<HH:MM>`** — окно слота; `/open` ставит его первым.
- **Ёмкость дня** — только реальные окна: работы юнита на «крошки времени» (дорога, паузы) не верстаются.
- **Исчезающие заметки** (`00-inbox/`) разбираются раз в неделю, на стратегировании. Если вводная уже записана, выброс пишется её исходом с причиной.

### Контур выходных

> Скелет. Различается наполнение дня; правила — ваши.

- **Утро выходного:** `<защищённый слот / свободно>`.
- **День первого выходного:** `<быт, стратегирование>`.
- **День второго выходного:** `<досуг>`.
- Уроки автора, переносимые как есть: запрет **по времени** (до такого-то часа — не инженерия) исполняется, запрет **по роду работы** — нет, если у вытесненной работы не назначен другой дом. У досуга должна быть цена или человек — бронь, билет, договорённость, — иначе его вытесняет работа, которая ощущается продуктивной и потому не опознаётся как конкурент. Норматив, который понижают и всё равно не берут, снимается, а не понижается в третий раз; условие возврата — событие (владелец сам называет предмет приоритетом).

## Прибор учёта (Super Productivity, опционально)

> Id объектов — свои у каждой установки прибора: заведите теги один раз (`create_tag`), узнайте id (`get_tags`) и впишите сюда ([[ADR-0029-time-tracking-instrument|ADR-0029]], [[ADR-0036-task-as-atomic-card|ADR-0036]]). Пока значения не заданы, потребители молчат о соответствующих колонках и строках, а не выдумывают их.

- **sp_invested_tag: `<id>`** — тег инвестированного времени. Читают `.claude/hooks/task-mirror-remind.sh` (строка про тег в напоминании) и `80-kernel/scripts/week-time.py` (колонка «инвестированное»).
- **sp_important_tag: `<id>`** — тег `Важное`; ставит `/task-new` при заведении работ.
- **sp_urgent_tag: `<id>`** — тег `Срочное`; ставит `/task-new`.
- **sp_role_prefix: ""** — префикс заголовка проекта(ов) наёмной роли в приборе, в кавычках (например, `"P07 —"`). Читает `week-time.py` (колонки «роль» и «инвестированное вне роли»); пусто — колонка роли считается нулём с предупреждением.
