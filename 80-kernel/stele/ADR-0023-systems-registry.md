# ADR-0023 — Реестр развиваемых систем (`10-governance/9-systems/`, SYS-NNN)

## Контекст

Архитектурные решения по эксплуатируемым системам (`<system-name>`) велись как ADR **в самих репозиториях** (`<repo>/docs/adr/`). Два изъяна всплыли при её редизайне:

1. **Opsec.** Репо системы бывает **публичным**. ADR раскрывают топологию, инфраструктуру, провайдера и — критично — **юрисдикцию хранения секретов** вместе с моделью угроз. Публиковать это нельзя.
2. **Рассуждение вне экзокортекса.** Решения размазаны по внешним репо, а не в едином месте размышления. Ведение ADR разрослось — это уже отдельная практика, требующая дома.

У hypomnemata **уже есть** своя Стела (`80-kernel/stele/`) для ADR *самой системы*. Паттерн «у системы есть стела» существует — нужно обобщить его на *другие* системы, которые инженер эксплуатирует и развивает.

## Решение

Завести **каталог систем** `10-governance/9-systems/` с карточками `SYS-NNN` (`type: system`) и **приватным каноническим домом ADR на систему**: `9-systems/SYS-NNN-<slug>/adr/`.

- **Первая внешняя система = SYS-001.** Её ADR переезжают из публичного `<repo>/docs/adr/` в `9-systems/SYS-001-<system-name>/adr/` (приватно, в vault). Формат — конвенция самой системы (например, англ., `NNNN-slug`); путь дизамбигуирует от kernel-Стелы. `docs/adr/` в репо ретайрится (указатель).
- **hypomnemata = SYS-000.** ADR **остаются в kernel-Стеле** `80-kernel/stele/` — это машинерия ядра, не внешняя система. Реестр SYS лишь *индексирует*; дом ADR различается принципиально (ядро для self, governance для внешних).
- **Каталог параллельный, не ещё один traceability-реестр** (цепочка INV-14 не трогается; systems рядом, как resource-tracker).
- **«Система» ≠ «проект»:** проект — работа к исходам; система — durable-артефакт, что существует и эволюционирует. Ортогональны: задача трассируется в проект, ADR — в систему.
- **Native-first и легко** (принятая митигация ⚠️ ниже): папка + md-карточки + Dataview-индекс (`9-systems/index.md`), **без машинерии, хуков, скриптов**, без scaffold наперёд (заведём при повторе). Старт — SYS-000 + первая реальная система, не обобщать под гипотетические.

## Альтернативы

Прогон ArchGate (критические: **Безопасность + Эволюционируемость**; сравнительный режим).

| ЭМОГССБ | A — статус-кво (ADR в публичном репо) | B — SYS-реестр в governance (**выбран**) | C — приватизировать репо системы |
|---|:--:|:--:|:--:|
| **Э**волюц *(крит)* | ⚠️ размазано, вне vault | ✅ единый дом, переносимо (INV-1) | ❌ каскад: ломает анонимный доступ, на который опираются потребители репо |
| **М**асштаб | ✅ | ✅ SYS-NNN + Dataview | ✅ |
| **О**бучаемость | ✅ | ✅ как реестр/resource | ⚠️ git-auth-машинерия |
| **Г**енерат | ⚠️ не композится | ✅ (держать лёгким, INV-3/7) | ⚠️ |
| **С**корость | ✅ | ✅ | ✅ |
| **С**овременность | ✅ | ✅ | ⚠️ |
| **Б**езопасн *(крит)* | ❌ opsec-утечка | ✅✅ чувствительные ADR из публичного убраны | ✅ но дорого |

- **A (статус-кво)** — ❌ по критической Безопасности (публичная утечка решений и юрисдикции). Недопустим.
- **C (приватизировать репо)** — ❌ по критической Эволюционируемости: публичность репо бывает несущей (например, анонимный read-only pull со стороны GitOps-контроллера); приватизация тянет git-auth — каскад ради не той цели.
- **Tiered (benign публично, чувствительные приватно)** — проходит вето, но дробит дом (напряжённость INV-2 «в одном месте») и требует пер-ADR суждения о чувствительности. Доминируется B.
- **B (выбран)** — единый приватный дом, чувствительные ADR **никогда не публикуются**, opsec закрыт.

## Последствия

- + Чувствительные решения (юрисдикция секретов, топология) — приватно; opsec-утечка закрыта.
- + Единый канонический дом на систему (INV-2); ADR в vault → переносимы из чистого клона (INV-1 улучшен).
- + «Система» становится first-class governance-объектом; композится с проектами и задачами через wikilinks + Dataview.
- − **⚠️ Леность / минимальная поверхность (INV-3/7):** реестр на пару систем граничит с преждевременным обобщением. **Принято с митигацией:** только native-first (папка + карточки + Dataview), без машинерии, старт минимальный, не обобщать наперёд.
- − Кросс-репо разрыв: код системы может жить в публичном репо, решения — в приватной governance (рассуждение в экзокортексе — это и есть смысл hypomnemata).
- − ADR, уже опубликованные в публичном репо, остаются в его истории (их нельзя «распубликовать»): канонический дом — governance, репо-копии ретайрятся отдельно. Поэтому решение стоит принять до первого ADR в публичном репо, а не после.
- Носитель — карточки SYS + `9-systems/index.md`; реестр индексирует, дом ADR у систем различается принципиально.
