# ADR-0018 — Конфиг установки (`80-kernel/config.md`)

## Контекст

Полируя `/open`, подключили проверку окон через MCP Google Calendar. У инженера много календарей разных типов — нужно знать, какие читать при поиске свободных слотов и как трактовать (busy / релевант слоту / справочно / игнор). Это **параметр установки** под конкретного инженера: не выводится из кода или состояния, читается скиллом детерминированно. Дома под такие параметры не было.

## Решение

Завести **`80-kernel/config.md`** — единый файл «параметры установки», секциями. Первая секция — «Календари»: реестр календарей с ролями и идентификаторами; читает `/open` при поиске окон. Схема ролей:

| Роль | Смысл |
|---|---|
| `busy` | события занимают время, блокируют слоты |
| `slot` | busy + релевантно слоту саморазвития (лекции, учёба) |
| `info` | показывать справочно, НЕ блокировать окна |
| `ignore` | не читать |

Строки реестра — `<имя календаря> | <роль> | <calendar-id>`; конкретные календари и их id — ваши.

**Правило дробления (генеративная дисциплина):** один файл секциями. Расщеплять на отдельные файлы — когда второй скилл-потребитель захочет свой срез **И** файл вырастет настолько, что чтение целиком стоит контекста. Триггер не «второй потребитель» сам по себе, а «второй потребитель + срез достаточно большой» (напр. секцию «Ритм» читают и `/open`, и `/strategize`, но при малом файле цена чтения целиком пренебрежима — не дробим). До тех пор каталог `config/` — преждевременная структура (INV-3).

Принцип: **дробить конфиг по потребителю, не по теме** — стоимость контекста есть число файлов, которые скилл вынужден прочитать ради нужного среза. Конфиг читается целиком и детерминированно (в отличие от памяти `70-memory`, где много мелких + индекс оправданы выборочным recall).

## Альтернативы

- **Каталог `config/` с файлом-на-тему сразу** — отклонён: преждевременная структура при одном потребителе (Генеративность ⚠️, балласт против INV-3).
- **`settings.json` (.claude)** — отклонён: смешивает доменный конфиг с harness-конфигом, json не Obsidian-native (Обучаемость/Генеративность ⚠️, против INV-18), связывает с harness (Эволюционируемость ⚠️).
- **`reference`-память в `70-memory`** — отклонён: память для выборочного recall и состояния агента, не для детерминированного конфига; мискатегоризация (Обучаемость ⚠️).
- **Инлайн в скилле** — отклонён: ровно тот дрейф формы в процедуру, который убран для dayplan/session-скелетов; нет дома под будущий конфиг (Эволюционируемость ❌, Генеративность ❌).

## Последствия

Профиль ЭМОГССБ (критические — **Генеративность, Обучаемость**, обе ✅; блокеров 0):

- **+** Генеративность ✅ — чистый дом под все будущие параметры установки; native-first md; правило дробления держит леность.
- **+** Обучаемость ✅ — один известный файл, md-таблица, самодокументируемые роли; низкая стоимость чтения.
- **+** Эволюционируемость ✅ — plain md в репо, переносим на чистом клоне (INV-1), без зависимостей; смена провайдера = правка одной секции.
- **+** Скорость ✅ — один Read, без парсера.
- **+** Современность ✅ — config-as-code, доменный конфиг разведён с harness-конфигом.
- **−/принято** Безопасность — id календарей в git; id без OAuth не дают доступа (не креды), репозиторий личный → принято без митигации. В публичном форке id календарей и адреса почты в конфиг не кладутся.
