# ADR-0017 — Принципы как submodules + MCP mim-knowledge

## Частичная отмена механизма (2026-09-24, [[ADR-0038-exocortex-shims-and-nested-repos|ADR-0038]])

**Снят только механизм монтирования: submodule заменён обычным вложенным репозиторием.** Пути, dot-зона, HTTPS-адреса, pull-by-need и роль `.principles/` как референса — в силе; разворачивает и обновляет их теперь `80-kernel/scripts/repos-bootstrap.sh`.

Довод: владелец держит принципы постоянно обновлёнными, а submodule по построению консервирует версию — свежесть живёт в рабочей копии одной машины и не доезжает до второй без отдельного коммита указателя. Обнаружилось это при снятии: `fpf` оказался на два коммита свежее, чем было записано указателем, и узнать об этом из vault было неоткуда.

**Цена, принятая явно:** фиксация версии апстрима исчезает, поэтому ссылка на снятый или переименованный паттерн FPF больше ничем не подпирается: принципы обновляются при каждом касании, и ссылка может пережить свой предмет. Воспроизводимость обоснования переезжает в текст: ADR, опирающийся на конкретный паттерн, называет версию апстрима прямо в себе.

## Контекст

Hypomnemata ушла от тяжёлого рантайма IWE (INV-7: нет update.sh, нет 320-файлового рантайма; апстрим — pull-by-need референс). Но опорная методология ценна и уже фактически зависимость: `contract.md` ссылается на FPF (A.6.8), ADR-ы и заметки используют FPF-различения. Владелец опирается на методологию МИМ и хочет (а) обращаться к методологии МИМ из своей системы, (б) опираться на лестницу принципов, (в) создавать паспорта доменов по SPF (аналог Pack предыдущей системы).

Прежний скилл `fpf` был сросся с инфраструктурой IWE: MCP `iwe-knowledge` (удалённый сервер Aisystant), цепочка Pack→SPF→FPF (в Hypomnemata нет Pack/SPF локально), отдельный справочник в памяти.

## Решение

**Три submodule в `.principles/` (dot-зона, Obsidian игнорит), HTTPS public, pull-by-need:**

| Слой | Path | Upstream |
|------|------|----------|
| Нулевые принципы | `.principles/zp` | публичный репозиторий ZP |
| Первые (FPF) | `.principles/fpf` | публичный репозиторий FPF |
| Вторые (SPF, → Pack) | `.principles/spf` | публичный репозиторий SPF |

Адреса апстримов — в `80-kernel/scripts/repos-bootstrap.sh`.

**MCP `mim-knowledge`** (`.mcp.json`) — **опционально, нужна учётка МИМ** — тот же сервер Aisystant (`https://mcp.aisystant.com/mcp`), что и `iwe-knowledge`, под новым локальным ключом (переименование = ключ в конфиге, сервер тот же). Даёт семантический поиск по корпусу МИМ + FPF/SPF (`knowledge_search`/`knowledge_get_document`/`personal_search`), read-only. Авторизация — учётная запись платформы Aisystant.

**Скилл `/fpf` адаптирован:** лестница `local (Стела/30-knowledge) → SPF → FPF → ZP`; два пути доступа — MCP (семантика) + локальные файлы (Grep/Read точной секции, офлайн); No-Jargon-перевод (INV-6) вынесен в `.principles/README.md`. Создание паспорта домена по `spf/pack-template` + `spf/process` → `30-knowledge/` — скилл `/domain`.

**Граница (что это НЕ):** вложенные репозитории принципов = pull-by-need референс (по INV-7), не вендоринг (спека FPF ~92 тыс. строк не входит в историю vault). MCP = тонкий клиент к внешнему read-only сервису, не хостим рантайм; native-first сохранён (obsidian-MCP не тащим — агент пишет md напрямую, INV-4).

## Альтернативы

- **Вендоринг (копии файлов в vault)** — отклонено: +92 тыс. строк в историю, застывает, ручное обновление.
- **Только обзор + перевод, без полной спеки** — отклонено: ломает режим lookup по точным секциям (A.7, ZP.2) офлайн.
- **Не брать MCP, только локальные файлы** — отклонено: теряется семантический поиск и доступ к корпусу МИМ / личным материалам.
- **Оставить имя `iwe-knowledge`** — отклонено владельцем: система не IWE; имя отражает источник (МИМ).

## Последствия

- + Доступ к методологии (ZP/FPF/SPF) и корпусу МИМ; основа для создания паспортов доменов.
- + Лестница принципов локально + семантический поиск — дополняют друг друга; офлайн-режим на локальных файлах.
- − Чистый клон требует развернуть принципы (в первой редакции — `git submodule update --init`, ныне `repos-bootstrap.sh`; INV-1 нюанс: стандартный git, не спец-рантайм — приемлемо).
- − MCP-путь зависит от Aisystant и авторизации; без учётки или при недоступности скилл работает на локальных копиях принципов.
- − Ре-введена внешняя зависимость, от которой система частично уходила — осознанный, узкий (read-only знания), не governance-машинерия.

## Источник

Прежний `iwe-knowledge` MCP + скилл `fpf`; публичные репозитории ZP, SPF, FPF. Решение — владелец, при сборке системы.
