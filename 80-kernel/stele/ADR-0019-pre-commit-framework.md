# ADR-0019 — Git-гейты через pre-commit framework + frontmatter-гейт

## Контекст

Миграция из предыдущего vault принесла битые свойства frontmatter (незакрытые кавычки в `aliases` → Obsidian «invalid properties», Dataview не отрисовывал бэклинки). Нужен **гейт валидности frontmatter** на коммите — ловящий и агента, и ручную правку в Obsidian. До сих пор гейты были ручными git-хуками (`80-kernel/hooks/pre-commit` через `core.hooksPath`, [[ADR-0013-wp-card-self-contained|ADR-0013]]). При вскрытии обнаружилось: тот хук матчил `wp-*.md` строчными, а карточки — `WP-NNN` ([[ADR-0006-naming-convention|ADR-0006]]), т.е. **гейт артефакта фактически не срабатывал**.

## Решение

Перейти на **pre-commit framework** (индустриальный стандарт) как менеджер git-гейтов:

- Инструмент `pre-commit` пиннится в корневом `mise.toml`, `postinstall` ставит git-хук. Bootstrap → `mise install`.
- Гейты — `.pre-commit-config.yaml`, **local**-хуки на Python (один язык с существующим чеком артефакта): frontmatter — `language: python` (pre-commit ставит `pyyaml` в изолированный venv, портабельно без system-зависимостей), остальные — `language: system` (system python3, только stdlib). Срабатывают только на staged-файлах коммита.
- **Хуки первой редакции:**
  - `frontmatter-check` (`80-kernel/scripts/frontmatter-check.py`): YAML-валидность + status-схема [[ADR-0012-metadata-convention|ADR-0012]] (для родов, где статус enum-ирован: контент/задача/ADR; прочие — только валидность). Калибровано против всего vault (0 ложных на ~370 файлах).
  - гейт артефакта (миграция прежнего ADR-0013-чека): regex исправлен на заглавный префикс — гейт ожил. Ныне — `task-artifact` (`80-kernel/scripts/task-artifact-check.py`, [[ADR-0036-task-as-atomic-card|ADR-0036]]).
- Снят `core.hooksPath`; ручной `80-kernel/hooks/pre-commit` удалён (перенесён в config).
- Усложнятся — вынесем в отдельный репо (`repo:` вместо `local`).

Позднее тем же механизмом, без новой машинерии, добавлены гейты `task-id-unique` (номер задачи уникален при параллельных сессиях), `tray-outcome` (слитый лоток без пустых исходов, [[ADR-0032-cadence-rituals-and-forreview|ADR-0032]]), `closed-date` (закрытая карточка несёт дату `closed`, ADR-0012) и `naming-convention` (`.claude/hooks/check-naming.sh`, ADR-0006). Актуальный перечень — `.pre-commit-config.yaml`.

**Профиль ЭМОГССБ** (критические — Эволюционируемость, Безопасность; блокеров 0):

- **+** Эволюц. ✅ — стандартный формат, хуки добавляются декларативно; переносим (mise pin, INV-1).
- **+** Современность ✅ — pre-commit = SOTA для git-гейтов (INV-18), не самопал.
- **+** Генеративность ✅ — основа под будущие гейты (lint имён, dataview-санити) без новой машинерии.
- **+** Безопасность ✅ — local-хуки на своих скриптах, без внешних repo-зависимостей на старте; secret-сканеры — по мере надобности.
- **−/принято** — добавлена зависимость `pre-commit` (через mise, pinned) и шаг bootstrap; компенсируется тем, что ручной хук был хрупок (мёртвый гейт артефакта это доказал).

## Альтернативы

- **Оставить ручной `hooksPath`-хук** — отклонён: хрупок (тихо умер на регистре `wp-`/`WP-`), каждый новый гейт = ручной bash, не переносится декларативно.
- **Claude PreToolUse-хук на frontmatter** — отклонён: ловит только правки агента, не правку в Obsidian (а битьё пришло именно из ручного/миграционного слоя).
- **check-yaml из pre-commit-hooks** — недостаточен: валидирует `.yaml`-файлы, не markdown-frontmatter.

## Последствия

- + Один механизм гейтов, декларативный, индустриальный; срабатывание только на коммитимых файлах.
- + Frontmatter-битьё больше не пройдёт в коммит; гейт артефакта ожил.
- − Механизм ADR-0013 (hooksPath) — **заменён**, не отменён: инвариант артефакта теперь энфорсится в pre-commit. ADR-0013 (решение) в силе, изменился носитель.
- Гейт-изменение проведено вне `/strategize` как защитный бэкстоп под уже случившийся баг (INV-5: усиление гейта, не ослабление).
