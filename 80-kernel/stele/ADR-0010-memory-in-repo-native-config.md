# ADR-0010 — Память в репо через нативный autoMemoryDirectory (git вместо sync-хуков)

## Контекст

Предыдущая система (IWE) держала память в auto-memory Claude Code (`~/.claude/projects/<slug>/memory/`) и бэкапила её хуком во внешний репозиторий + скрипты бэкапа. Это костыль: ручной sync, дрейф, «синк памяти — адская боль».

## Решение

Канон памяти — **в git-репо vault: `70-memory/`**. Claude Code направляется туда **нативной настройкой** `autoMemoryDirectory: "<vault-root>/70-memory"` в `.claude/settings.json` (официальный параметр; абсолютный путь или `~/`). Claude Code пишет `MEMORY.md` + topic-файлы прямо в `70-memory/` → git версионирует, `push` = бэкап + синк. **Sync-хуки и backup-скрипты не нужны** — git единственный механизм (INV-7). Настройка коммитится и едет на устройства; нестандартный путь клона переопределяется в `settings.local.json` (gitignored).

Симлинк и install-скрипт первой редакции удалены — нативный параметр единственный механизм. **Verify:** на первой сессии в vault подтвердить, что `MEMORY.md` пишется в `70-memory/` через настройку (если нет — чинить параметр/путь, симлинк не возвращать).

## Альтернативы

- **Auto-memory канон + бэкап-хук в репо (предыдущая система)** — отклонён: ручной sync, дрейф, костыль (исходная боль).
- **Симлинк `~/.claude/projects/<slug>/memory` → `70-memory` (1-я редакция этого ADR)** — заменён нативным `autoMemoryDirectory`. Verify-before-assert: первая редакция отвергла «нативный конфиг» как «не гарантированный», но проверка доки Claude Code нашла официальный параметр `autoMemoryDirectory` → меньше движущихся частей, native-first (INV-18).

## Последствия

- + Память версионируется и синкается git'ом сама; чистый клон = память на месте, нативно (INV-1).
- + Ноль sync-хуков/бэкап-скриптов и ноль симлинк-костыля (INV-7/INV-18).
- − Путь клона зашит в настройку (`<vault-root>`; иной путь — override `autoMemoryDirectory` в `settings.local.json`).
- − `MEMORY.md` остаётся uppercase (конвенция Claude Code) → исключение в [[ADR-0006-naming-convention|ADR-0006]] + хуке имён.
- Официально (по доке): `MEMORY.md` грузится первые 200 строк / ~25 тыс. символов (замер: срез после ~24,7 тыс. символов — режут символы, а не байты; в кириллице это ~34 КБ); topic-файлы — по требованию. Индекс держать ≤200 строк.

## Поправка 2026-09-26 — что принадлежит памяти и как запись её покидает

**Контекст.** Индекс дорос до ~36 КБ при потолке чтения ~24 КБ: треть записей молча не грузилась. Причина — в правиле записи: несколько скиллов держали его в разных редакциях («урок/правило → `70-memory/`»), и ни одна не отсекала технический факт. Около трети записей по роду были не о поведении агента. Потолок «≤200 строк» стоял, но выхода записи из индекса не было — память росла монотонно, а переполнение не видно: оно отрезает хвост.

**Тест принадлежности — асимметрия цены незнания, а не предмет записи.** Запись принадлежит памяти, если забыть её дороже, чем переоткрыть:

- забыл выданное **полномочие** → переспрашиваю уже разрешённое → память;
- забыл **запрет** → делаю разрушительное → память;
- запрет или полномочие от **иного правомочного лица** (владелец продукта-партнёр, политика работодателя, правила чужого репо) → память на тех же правах; запись называет источник и границу его власти, допускает её владелец. Правило, действующее только внутри одного репо и записанное там, не дублируется — агент встретит его у носителя;
- забыл знание **о владельце и о работе с ним** → ошибаюсь в каждой сессии → память;
- забыл **технический факт** о системе или инструменте → теряю время, переоткрываю из источника → к носителю; выбор решает **область верности факта**: об одном экземпляре, который мы эксплуатируем, — `10-governance/9-systems/SYS-NNN/`; об инструменте везде, где он вызывается, — `30-knowledge/tooling/`; только в момент исполнения одного скилла — его `references/`; ограничение предметной области, переживающее смену инструмента, — паспорт домена; умирает с проектом — карточка проекта; верно при смене работодателя — общее ядро знаний `30-knowledge/core/` (опционально, [[ADR-0027-knowledge-core-submodule|ADR-0027]]) по его правилам opsec.

**Решает последствие незнания, а не род записи.** Технический факт, незнание которого разрушительно — инструмент молча ломает чужое и рапортует успех, — остаётся в памяти как запрет, с подробностями у носителя. Прецедент: пакетное удаление записей через API внешнего сервиса, правка объекта по неверному идентификатору, общие модули инфраструктуры-как-кода ушли из памяти по первой редакции теста и вернулись одной записью-запретом «ловушки, рапортующие успех».

**Тихий отказ, ведущий к ложному выводу.** Факт, незнание которого стоит не времени, а неверного заключения (проверка молча зеленеет, поиск молча пуст, прибор пишет ноль вместо «не снято»), — технический и живёт у носителя. В память идёт не факт, а **метод, который такой отказ ловит**, — одной записью на механизм, с прецедентами у носителей.

**Когда строка силы и есть факт — побеждает строка силы.** Запрет, сформулированный самим фактом, остаётся в памяти дословно; у носителя — подробности. Дубль допустим, потеря силы — нет.

Предмет не решает: запрет на императивный `kubectl apply` в одном конкретном кластере касается только его, но остаётся в памяти, потому что его незнание разрушительно. Запись, где полномочие соседствует с техникой, **расщепляется**. В индексе вместо строк на каждый переселённый факт — маршрутизатор «домен → адрес», чтобы агент знал, куда идти.

**Не писать — законный исход теста.** Кандидат, который уже лежит у носителя, выводится из источника быстрее, чем ищется запись, или не переживёт сессии, не пишется никуда; дубль у носителя хуже пропуска.

**Порог выбытия.** Индекс держится в пределах **60 записей и 12 КБ**. Превышение любого из двух — повод для ревизии на ближайшей сессии стратегирования: каждая запись заново проходит тест, не прошедшая **уезжает по адресу носителя, а не удаляется**; прецеденты одного механизма сводятся в общий носитель. Порог взят с запасом ~10 % над объёмом после первой ревизии, чтобы срабатывал на росте, а не сразу.

**Счётчик.** Порог меряет `80-kernel/scripts/orz-check.sh` на каждом старте сессии: записи — файлы `70-memory/` кроме индекса, размер индекса — **в символах**, потому что режут символы. 12 КБ переведены в **8 700 символов**: 12 288 байт при измеренных ~1,4 байта на символ кириллического индекса дают ~8 780, округлено вниз. До среза в ~24,7 тыс. символов это почти втрое — порог срабатывает на росте задолго до потери записей.

**Срок.** Временный запрет или полномочие пишется с `valid_from` и `valid_until` либо `until: <условие>`. Запись с наступившим условием снимается на первой ревизии и уходит в историю git — единственный законный выход без носителя: снятому запрету переезжать некуда.

Единая редакция правила стоит в `/checkpoint`, `/close`, в описании `70-memory/` в `.claude/CLAUDE.md` и в шапке `70-memory/MEMORY.md`.
