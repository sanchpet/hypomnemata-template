# ADR-0002 — Топология: гибрид моно-ядро + dot-внешнее

## Контекст

Как разложить vault по репозиториям и каталогам, чтобы Obsidian не индексил код/сырьё, но агент/IDE их видели, и чтобы домен можно было вынести позже (INV-8).

## Решение

**A — гибрид моно-ядро:** один приватный git-репо. Ядро (видимое Obsidian): `kernel/ memory/ governance/ library/ knowledge/ inbox/ archive/` (пути с номерами — [[ADR-0006-naming-convention|ADR-0006]]). Внешнее референсом в dot-каталогах (точка → Obsidian игнорит): `.principles/` (ZP/FPF/SPF — вложенные репозитории), `.repos/` (код-репо, gitignored), `.resources/` (внешнее сырьё, gitignored). Один корень = вся система под папкой vault.

## Альтернативы

- **B: всё в одном репо без dot-границы** — СТОП (2❌ ЭМОГССБ): Obsidian индексит код и сырьё, load на code+resources.
- **C: репо-на-домен** — ломает INV-1/INV-7 (5 клонов вместо одного), over-engineering для n=1.

## Последствия

- + Вынос домена позже без переезда (INV-8); один корень; код/сырьё вне индекса Obsidian.
- + `kernel (код) ≠ memory (данные)` — разный writer (INV-19) и дисциплина проверок (INV-17).
- − Caveat: не гонять `git clean -fdx` в корне — снесёт вложенные репозитории в `.repos/` и `.principles/`.
- Уточнён [[ADR-0030-repos-root-per-machine|ADR-0030]]: «один корень» относится к субстрату знания, но не к чужим рабочим деревьям — корень раскладки клонов объявляет машина. Там, где клоны живут вне vault, `.repos/` хранит только реестры, и caveat выше к нему не относится.
