# Контракт Hypomnemata — инварианты (INV-1…21)

> Канонический источник инвариантов системы. Ссылки `INV-N` в `CLAUDE.md`, ADR-Стеле и `70-memory/` разрешаются здесь.
> Контракт-first (FPF A.6.8): инварианты — обещания-outcomes (полярность «больше-лучше»), не механика. Механику, которая их держит, описывают ADR Стелы ([`README.md`](README.md)), хуки и детекторы.

## Базовые (INV-1…8)
- **INV-1 Переносимость** — состояние (память / планы / задачи / трекеры) восстановимо из чистого клона vault без спец-рантайма.
- **INV-2 OwnerIntegrity** — один домен знания в одном месте в любой момент.
- **INV-3 Леность контекста** — несётся только добавленное инженером; без балласта «по умолчанию».
- **INV-4 Прямая правка субстрата** — агент пишет md напрямую; obsidian-MCP не обязателен; Properties/Dataview из коробки.
- **INV-5 Гейты-инварианты** — Open/Close/capture обеспечены хуками; правка самого гейта — на сессии стратегирования; правка вне сессии допустима, если следующая сессия её ратифицирует.
- **INV-6 Профессиональные дефолты** — словарь / гейты / дефолты под профессиональный профиль владельца (у автора — DevOps/Platform-инженер, отсюда исходное имя «DevOps-дефолты»); режим «на пальцах» не несём.
- **INV-7 Минимальная поверхность** — нет update.sh, нет 320-файлового рантайма (так выглядел апстрим-шаблон, от которого система отпочковалась), нет мульти-тенант-обобщений; апстрим — pull-by-need референс (методология ZP/FPF/SPF — вложенные репозитории `.principles/`, [[ADR-0017-principles-submodules-mcp|ADR-0017]], [[ADR-0038-exocortex-shims-and-nested-repos|ADR-0038]]). Допустимы тонкие read-only клиенты к внешним сервисам (опционально — MCP `mim-knowledge` → корпус МИМ, нужна учётка платформы), но не хостинг рантайма; native-first для правки файлов сохраняется (INV-4).
- **INV-8 Strangler-coexistence** — домен живёт в старом ЛИБО новом носителе (прежний vault при миграции, прежний прибор учёта при его смене — [[ADR-0029-time-tracking-instrument|ADR-0029]]); переключение атомарно по-доменно; удаление старого — решение сессии стратегирования.

## Ритм (INV-9…10)
- **INV-9 ОРЗ-фрактал** — Открытие→Работа→Закрытие на **5 масштабах** (сессия / день / неделя / **юнит** / **спринт**), облегчённо; списки рабочих продуктов на день и главных результатов на юнит — структурный инвариант. Бо́льшая каденция **поглощает** меньшие: спринтовая сессия исполняет шаги юнита и недели, юнитная — шаги недели, каждый шаг однажды. Месяц и квартал сняты как масштабы ([[ADR-0037-sprint-unit-planning-frame|ADR-0037]]): они периоды календаря, а не работы, и их пропуск был недетектируем.
- **INV-10 Стратегирование** — **еженедельно обязательно**, одним ритуалом `/strategize`, чей режим **вычисляется** из положения дня стратегирования (`80-kernel/config.md`, у автора — суббота) в цикле и наличия артефактов, а не спрашивается ([[ADR-0037-sprint-unit-planning-frame|ADR-0037]]): сверка остатка юнита (45 мин) · закрытие юнита и открытие следующего (90) · закрытие спринта (135) · открытие спринта в разгрузочную неделю (до 180). Свод недели пишется в каждый день стратегирования; **плана недели нет** — работу размещает юнит, раскладку по дням делает `/close` накануне. Пересматривает реестр неудовлетворённостей и сквозной документ-стратегию ([[ADR-0016-strategy-document|ADR-0016]]: миссия / видение / **цели года и спринта** / состояние — живой, правится каждую сессию). **Тройка на каждом масштабе:** год 3 цели · спринт 3 цели · юнит 3 главных результата · день 3 рабочих продукта; неделя целей не несёт. Пропуск *детектируется* на всех каденциях (носитель — INV-17).

## Поверхности и доменная модель (INV-11, 14)
- **INV-11 Стартовая страница** — обязательная проекция фокуса через tags / properties / dataview; место-вид, не источник.
- **INV-14 Реестры + цепочка** — пять реестров: направления / устремления / неудовлетворённости / проекты / задачи ([[ADR-0040-project-is-the-goal|ADR-0040]]: проект и есть цель, реестр целей закрыт; прежде реестров было шесть — [[ADR-0035-aspiration-tier-and-chain|ADR-0035]], а до него четыре). Цепочка проверяется **только вниз** — младший объект называет старшего, обратной проверки нет: устремление без неудовлетворённости есть свидетельство покоя, а не разрыв. Разрыв *детектируется* (INV-17); не прошедшее проверку выносится в лоток строкой с вопросом, а не отбраковывается.

## Поток знаний (INV-12, 13, 20, 21)
- **INV-12 Творческий конвейер** — заметка→черновик→заготовка→эссе; стадия = свойство (не папка); + индекс публикаций / каналов (перечень каналов — ваш) / источников.
- **INV-13 Образовательные заметки** — шаблоны сводных страниц источников (курс / книга) + кнопки-генераторы дочерних заметок.
- **INV-20 Governance + паспорт** — формализованный паспорт домена (agent-writer, Derived) + личная база знаний как индекс размышлений (engineer-writer, Observed).
- **INV-21 Evergreen notes** — атомарные, концепт-ориентированные, нетерминальные (TTL-exempt); ≠ конвейерные заметки INV-12. Статус мягкий (кандидат на затвердевание).

## Время (INV-15)
- **INV-15 Трекинг физического времени** — реальное затраченное время по задачам; native-first (INV-18); различать учтённое / инвестированное; свести с WakaTime.

## Поведение агента (INV-16, 19)
- **INV-16 Мышление / регистр** — рассуждение поверх FPF (планирование) + терминов МИМ + профессионального словаря владельца (у автора — DevOps); дефолт — инженерный тон; «на пальцах» только по явному запросу.
- **INV-19 Writer-ownership** — один writer на файл: **agent-writer** (state / реестры, через Claude) | **engineer-writer** (письмо, в Obsidian) | **mixed** (исключение, явный статус). `mixed` ≠ «ничей»: класс объявляется во frontmatter (`writer: mixed`) и держит **внутрифайловую границу зон** — agent-writer ведёт состояние (таблица прогресса), engineer-writer ведёт прозу; блочное правило к файлу, не объявившему writer, не применяется. Первый носитель — карточки источников `20-library/resources/**`. Второй носитель — рабочие находки (`type: finding`): прозу пишут владелец и агент по очереди, граница — frontmatter за агентом, проза общая. Frontmatter файлов engineer-writer агент правит по разрешению владельца, тело — нет.

## Инженерная дисциплина (INV-17, 18)
- **INV-17 Система-как-код** — система в Git → TDD / CI / code-review / pre-commit / checks применяются к ней самой. Носитель enforcement для INV-5 / 10 / 14 / 18 / 19. n=1: review = AI/self-review, CI = внешний heartbeat.
- **INV-18 Naming + native-first** — naming-convention ([[ADR-0006-naming-convention|ADR-0006]]) + «фичи Obsidian (wikilinks / tags / properties / dataview) раньше своего». Правило решения build-vs-adopt.
