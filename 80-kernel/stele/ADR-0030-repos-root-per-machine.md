# ADR-0030 — Корень раскладки клонов — свойство машины

## Контекст

Скилл, работающий с dotfiles, цитировал абсолютный путь к клону. Путь не пережил смену домашнего каталога, и скилл отправлял работать в несуществующий каталог; разбор показал, что дело шире опечатки.

На рабочей машине клоны лежат не под `.repos/`, а в домашнем каталоге: личные — под `<repos-root>`, корпоративные — под `<work-root>`. Это не небрежность: к рабочему корню привязан включатель корпоративной git-личности (`includeIf "gitdir:…"`), чьё значение держится в машинно-локальных данных менеджера dotfiles. Каталог `.repos/` при этом хранил трекаемые маркеры и ни одного клона.

Реестры клонов в vault описывали раскладку под vault'ом как данность для всех машин. Из-за этого директорийно-скоупленный `CLAUDE.md` — конвенции клонов, которые агент подхватывает по cwd — на рабочей машине не подгружался никогда: файл лежит под vault'ом, а работа идёт вне его.

## Решение

**Корень раскладки объявляет машина, а не Стела.** Раскладка по источнику (ADR-0022: личное и рабочее, по поддереву на каждый источник) сохраняется как принцип; машинно-зависимым становится только корень, от которого она отсчитывается. Обе раскладки легальны: `.repos/` внутри vault'а на одной машине, `<repos-root>` + `<work-root>` на другой.

**Правило разрешения пути:** источник истины — инструмент, владеющий машинно-локальной конфигурацией (у автора — `chezmoi source-path` для dotfiles, машинно-локальная переменная для корп-корня), реестр в vault'е ему уступает. Абсолютные пути в скиллах и документации не цитируются — вместо пути называется команда, которая его вернёт.

**Реестры остаются в vault'е** (приватность корп-деталей, ADR-0023) и монтируются в корень раскладки симлинком, когда корень лежит вне vault'а:

```
ln -s <vault-root>/.repos/<source>/CLAUDE.md <repos-root>/CLAUDE.md
```

Симлинк ставится вручную при заведении машины — как и клонирование репозиториев, которое всегда было ручным шагом. Управлять им через менеджер dotfiles отклонено: имя корп-корня пришлось бы внести в **публичный** репозиторий dotfiles, который намеренно не содержит названий работодателя.

`.repos/README.md` получает роль указателя: он объявляет модель и правило разрешения, поэтому машина, где каталог пуст, ведёт читателя к действующему корню, а не выглядит поломанной.

## Альтернативы

Прогон АрхГейт (критические: **Эволюционируемость + Генеративность + Безопасность**; сравнительный режим).

| ЭМОГССБ | A — вернуть клоны под `.repos/` | B — корень per-machine (**выбран**) | C — гибрид: личное внутрь, корп наружу |
|---|:--:|:--:|:--:|
| **Э**волюц *(крит)* | ❌ неприменимо на рабочей машине | ✅ корень = одно значение, обратимо | ⚠️ два правила вместо одного |
| **М**асштаб | ⚠️ десятки вложенных репо под vault | ✅ вложенных репо нет | ⚠️ половина остаётся |
| **О**бучаемость | ✅ одно место | ⚠️ корней два, нужен инструмент | ⚠️ помнить оба правила |
| **Г**енератив *(крит)* | ⚠️ фиксирует моно-корень догмой | ✅ следующая машина ложится без правки Стелы | ⚠️ расщепление тиражируется |
| **С**корость | ⚠️ скан дерева с вложенными репо | ✅ | ⚠️ |
| **С**овременность | ✅ | ✅ | ✅ |
| **Б**езопасность *(крит)* | ⚠️ корп-код внутри личного дерева | ✅ разведены физически | ✅ |
| **Вердикт** | не проходит | **рекомендуется** | доминируется B |

- **A — вернуть клоны под `.repos/`** — отклонён: на рабочей машине раскладка может быть неприменима (её ограничивает рабочий контур), а корп-код внутри рабочего дерева личного репозитория отделён от истории лишь `.gitignore` — граница толщиной в одну оплошность оператора (сюда же caveat ADR-0002 про `git clean -fdx`).
- **C — гибрид** — отклонён: доминируется B по всем строкам, где они расходятся, и заводит два правила вместо одного.

## Последствия

- + Раскладка перестаёт ломаться при переезде и заведении машины: меняется машинно-локальное значение, не Стела.
- + Корп-клоны выходят из рабочего дерева личного репозитория — граница держится топологией, а не `.gitignore`.
- + Реестр монтируется туда, где идёт работа, и подгружается агентом на рабочей машине.
- − Корень раскладки больше не один: чтобы найти клон, нужно спросить инструмент, а не прочитать путь. Принято осознанно (АрхГейт, ⚠️ Обучаемость → митигация: правило разрешения записано здесь, `.repos/README.md` работает указателем).
- − Натяжка INV-1: содержимое реестров восстановимо из чистого клона vault'а, но их монтирование — шаг настройки машины. Состояние не теряется, автоматизм подхвата — да.
- − Пути в машинно-зависимых конфигах редактора (например, `git.scanRepositories`), если такой файл трекается в vault'е, на другой машине мертвы. Хвост, требующий отдельного решения.
