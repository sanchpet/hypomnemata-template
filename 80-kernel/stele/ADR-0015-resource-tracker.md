# ADR-0015 — Трекер источников (R-NNN) + политика слотов саморазвития

> Уточнён [[ADR-0020-resource-state-in-cards|ADR-0020]] (2026-06-28): per-source состояние переехало в карточки, трекер стал тонкой витриной. Политика слотов ниже — в силе.

## Контекст

Материалы саморазвития (книги, курсы, руководства, источники) должны браться из **трекера**, заранее наполняемого на стратегировании — чтобы в слоты саморазвития и медленное чтение шли осознанно отобранные качественные материалы, а не что попало под руку. Трекер (`10-governance/resources-tracker.md`) существовал со схемой R-NNN, но ресурсы-заметки на него не ссылались — привязки не было.

## Решение

### Политика (INV-9, слоты саморазвития)

Источники саморазвития берутся **только из R-трекера**, пред-отобранного на стратегировании (повестка, пункт «актуализация материалов»). Слот-планирование (`/open`, `/strategize`) тянет следующий материал из трекера, не «что вспомнилось». Гарантия — осознанный отбор качества заранее.

### R-NNN = инвентарный номер источника

- **Источник верхнего уровня** (книга, курс, руководство, вечный источник) = нумерованная сущность `R-NNN`, имя файла `R-NNN-<english-slug>.md` (заглавный инвентарный префикс, [[ADR-0006-naming-convention|ADR-0006]]), поле `id: R-NNN`, заголовок в `aliases`.
- **Под-материалы** (главы книги, конспекты лекций) — НЕ имеют своего R; привязаны к R родителя ссылкой. R-NNN только у источника.
- Связь источник↔трекер: трекер = Dataview-витрина над заметками-источниками (один источник истины = заметка с `id`/`status`; трекер — вид) + политика (бюджет/слот-структура, например стандартный бюджет на раздел многотомного руководства). Пред-отбор = stub-источник со `status: later`.

### Тип `source` — вечные источники

Источники без срока завершения (сообщества, блоги, программы, в которых состоишь) — `type: source`: создают заметки, трекаются, но **не завершаются** — активны (`status: active`), пока релевантны / состоишь в них. Контраст: `book`/`course`/`chapter` — конечные (имеют `completed`), `source` — вечный (нет `completed`). Жизненный цикл закодирован в `type` (не отдельной осью scope).

### Даты — в метадате

Имя файла несёт только классификатор (`R-NNN-slug`), без даты. Даты работы с источником — в frontmatter: `started: YYYY-MM-DD`, `completed: YYYY-MM-DD` (у конечных, по завершении). Это заменяет прежний дата-префикс в имени (отменяет дата-сортировку имени в пользу инвентарного R-NNN + сортировки по `started` в Dataview).

## Последствия

- + Слоты саморазвития питаются осознанно отобранным; источник↔трекер связаны через R-NNN; вечные источники моделируются (тип `source`).
- + Ресурсы входят в единую инвентарную модель (как задачи/направления): `R-NNN-slug`, `id: R-NNN`.
- − Бэкпорт существующих источников: присвоить R-NNN, перенести даты в метадату, причесать алиасы, неоднозначный статус → inbox (отдельный проход).

## Источник

Трекер `10-governance/resources-tracker.md` (перенос из предыдущей системы, R-NNN-схема). Политика формализована при сборке системы, Ф3.
