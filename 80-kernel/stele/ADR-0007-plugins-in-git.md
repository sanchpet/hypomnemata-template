# ADR-0007 — Код плагинов Obsidian в git

> Заметка шаблона: решение принято для личного приватного vault. В публичном репозитории код сторонних плагинов — это чужой JS под их собственными лицензиями (несколько десятков мегабайт). Что именно несёт этот снимок — код плагинов или только `community-plugins.json` + настройки, — сказано в README шаблона; ADR фиксирует решение автора для своего vault.

## Контекст

Курированный набор community-плагинов ([[ADR-0005-plugin-curation|ADR-0005]]) переносится в vault. Вопрос: коммитить код плагинов (`main.js`, `manifest.json`, `data.json`, `styles.css`) в git или игнорировать и переустанавливать?

## Решение

**Коммитим код плагинов.** Obsidian сам по `community-plugins.json` плагины не докачивает — без файлов на диске свежий клон = плагины не работают. Для INV-1 (чистый клон = рабочая система) код плагинов едет в git вместе с настройками (`data.json`).

## Альтернативы

- **Gitignore код плагинов, коммитить только enabled-список + `data.json`** — отклонён: ломает INV-1 (клон без сети / ручной переустановки нерабочий; git-синк между устройствами не поднимет плагины).

## Последствия

- + Клон/синк = сразу рабочая система, офлайн, без переустановки (INV-1).
- − Репо несёт бинарный JS плагинов; обновления плагинов дают шум в истории git (приемлемо для личного vault).
- Безопасность: секреты в `data.json` исключены курированием — `obsidian-local-rest-api` (API-ключ) и `claude-sidebar` в drop-списке (ADR-0005). Перед публикацией `data.json` проверяется на личные пути и имена.
