# ADR-0040 — Проект и есть цель: реестр целей сливается с реестром проектов

## Контекст

[[ADR-0035-aspiration-tier-and-chain|ADR-0035]] завёл цель отдельным объектом между неудовлетворённостью и проектом. За две недели пара «цель + проект» ни разу не разошлась по существу: в заготовке целей спринта для личных целей записано «цель и проект суть одно», а на открытии спринта цели заводились парами «цель + проект» с одним и тем же текстом в двух карточках. Решение владельца: «Больше не различаем проект и цель. Проект формулируется так, что из него ясно, какая цель».

Второй довод — от детектора. Проект без цели краснел в цепочке, и законный побочный проект приходилось либо подвязывать к чужой цели, либо держать исключением. Объект, который чаще всего дублирует соседа, а в остальных случаях мешает, есть лишний ярус (INV-3).

## Решение

**1. Проект есть цель.** Имя проекта формулируется результатом, из которого цель видна без пояснений: «Публичный блог запущен, конвейер поставляет публикации», а не «Блог». Проект кончается достижением своего критерия.

**2. Поля цели переезжают в карточку проекта:** `criterion` (наблюдаемый критерий достижения), `period` (спринт, в котором проект взят, — например `<year>-s1`), `budget_h` (гипотеза часов). Поле `goal` снимается.

**3. Родитель проекта — одна главная неудовлетворённость** (`dissatisfaction`), существующая до проекта; правило происхождения ADR-0035 п. 5 переходит с цели на проект без изменений. Где боли нет, а есть тяга к устремлению, проект называет устремление напрямую (`aspiration`) — состояние законное, но в приоритет оно идёт отдельным названным доводом.

**4. Цепочка:** направление → устремление → неудовлетворённость → проект → задача. Реестров пять (INV-14 правится): направления, устремления, неудовлетворённости, проекты, задачи.

**5. Бессрочные русла** (`scope: infinite`) критерия не имеют и проектами-целями не являются; задачи юнита берутся только в проекты с критерием. Судьба бессрочных русел — открытый вопрос модели, решается отдельно.

**6. Реестр `4-goals` уходит в архив.** Достигнутые и снятые цели остаются там со своими датами; живые цели переезжают критерием в соответствующие проекты. Номер `4` в дереве оставлен дырой — след эволюции.

**7. Наёмная роль стратегируется наравне с личным.** Роль — проект-цель с критерием и `period` спринта; вне ранжирования портфеля она остаётся, но из стратегирования больше не выпадает. Если прибор ведёт и рабочие задачи, они заводятся в нём поимённо внутри этого проекта (контроль — содержание названий, ADR-0029 п.7), туда же встраивается инвестированное время внутри рабочих задач. Отменяет [[ADR-0029-time-tracking-instrument|ADR-0029]] п.7 («рабочие вёдра») вместе с его поправками.

## Альтернативы

- **Оставить пару, но заполнять одну карточку** — дублирование остаётся, просто становится невидимым (INV-2).
- **Цель как раздел карточки проекта без своих полей** — детектор и колесо модели не прочтут критерий и срок; поля дешевле прозы.

## Последствия

- Детектор цепочки проверяет: у активного проекта есть родитель (`dissatisfaction` либо `aspiration`); задача юнита ссылается на проект с `criterion`.
- Скелет цели снимается; повестка, скиллы, стартовая страница и [[self-model|Модель меня]] читают проект вместо цели. Зелёное число колеса — активные проекты с `period` текущего спринта.
- Профиль ArchGate не прогонялся: решение принято владельцем по ходу сессии. Прогон — задачей первого юнита спринта, вместе с миграцией.
