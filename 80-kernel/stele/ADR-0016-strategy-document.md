# ADR-0016 — Документ-стратегия (миссия / видение / цели квартала / состояние)

> ⚙️ **Уточнён [[ADR-0037-sprint-unit-planning-frame|ADR-0037]].** Месяц и квартал сняты как масштабы планирования: «цели квартала» заменены **целями года и спринта** (по три), MonthReview и ритуал `/month` упразднены, углублённый проход делает закрытие юнита, постановку целей — открытие спринта. Ядро решения в силе: один живой `strategy.md`, граница «намерения ≠ журнал», правка на каждой сессии стратегирования.

## Контекст

Предыдущая система держала всё в одном документе стратегии (~200 строк): он смешивал живую стратегию (миссия, видение, цели), журнал исполнения (результаты, ревью недель, задачи→результаты) и дубли (отдельные проекты, бэклог, полный список неудовлетворённостей). Смесь намерений и фактов раздувала файл — та же болезнь, что лечит раздел плана и отчёта периода.

При миграции в Hypomnemata перенесли декомпозицию сущностей (направления, проекты, цепочка в `index.md`) и недельный контур (`/strategize`), но **средний и длинный горизонт потерялся**: не было документа с миссией, видением (год+), целями периода и оценкой текущего состояния. `index.md` — механическая карта-вид (детектор разрывов цепочки), не стратегический нарратив.

## Решение

**Единый живой документ `10-governance/strategy.md`** — сквозная личная стратегия. Скелет — `80-kernel/scaffolds/strategy-tmpl.md` (agent-скелет, [[ADR-0014-template-kinds|ADR-0014]]); ритуал инстанцирует.

**Владеет (INV-2):** миссия · видение (горизонт год+) · подход (рычаги→направления) · цели периода (результат→движитель→критерий; в первой редакции — квартала) · текущее состояние относительно целей. Направления/проекты владеют своим содержанием — в документе только **индексируются** (Dataview-вид, не копия).

**Граница (что НЕ здесь):** журнал исполнения (результаты, ревью периодов, задачи→результаты) → отчёты периодов в `7-plans/archive/` (ныне WeekReport / UnitReport / SprintReport). Полный реестр неудовлетворённостей → `3-dissatisfactions/`. Проекты → `5-projects/`. Бэклог → `6-tasks/backlog.md`. `strategy.md` = «куда иду» (намерения), отчёт периода = «что произошло» (факты).

**Каденция (по частоте правок, не по запрету трогать):**

- **Каждая сессия `/strategize` (еженедельно)** — документ просматривается и корректируется; план периода вытекает из целей. Первичная точка правки.
- **Углублённый проход** (в первой редакции — `/month`, ныне закрытие юнита) — честная сверка состояния + проверка целей; **на границе большого периода** (в первой редакции — квартала, ныне открытие спринта) — постановка новых целей и пересмотр видения.
- Слои отличаются частотой: миссия/видение меняются редко, состояние — часто; но трогать можно любой слой на любой сессии.

**Создание** — на первом стратегировании в новой системе (не пред-создаётся агентом): миссию/видение/подход формулирует владелец (агент предлагает кандидаты из сырья прежнего документа и направлений). При создании добавляется ссылка в `start.md`.

## Альтернативы

- **Не заводить, держать стратегию в `index.md`** — отклонено: `index.md` = механический вид для детекции разрывов, не место для миссии/видения/состояния (разные владельцы, разное назначение).
- **Цели периода как отдельные нумерованные сущности (G-NNN)** — отклонено на момент решения: лишняя инвентарная ось против INV-3; цели живут секцией документа, линкуют свой движитель. (Реестр целей позже вводился и снова закрыт: проект и есть цель — [[ADR-0040-project-is-the-goal|ADR-0040]].)
- **Правка только на углублённом проходе** — отклонено владельцем: стратегия — живой документ, недельная сессия должна её видеть и корректировать; углублённый проход лишь углубляет.
- **Перенести прежний документ стратегии целиком** — отклонено: тянет журнал исполнения и дубли (Inventory≠Progress, OwnerIntegrity). Перенесена только структура живых слоёв + текст миссии/видения/рычагов как сырьё-кандидат.

## Последствия

- + Появился средний/длинный горизонт (видение + цели периода) и явная оценка состояния — то, что потерялось при миграции.
- + План периода обоснован сверху (цель ⇒ работа периода), а не только снизу (бэклог).
- + Ритуал углублённого прохода завязан на живой документ, а не на одноразовый отчёт.
- − Дисциплина границы: журнал исполнения держать в отчётах периодов, иначе документ снова раздуется (риск рецидива прежнего документа).

## Источник

Документ стратегии предыдущей системы (структура живых слоёв + диагностические измерения состояния). Решение по каденции — владелец, при сборке системы.
