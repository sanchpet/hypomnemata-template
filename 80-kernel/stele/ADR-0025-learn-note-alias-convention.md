# ADR-0025 — Конвенция alias учебных заметок + свойства источника `short`/`provider`

Уточняет [[ADR-0020-resource-state-in-cards|ADR-0020]] (расширяет схему карточки-источника) и [[ADR-0014-template-kinds|ADR-0014]] (шаблон learn-note читает свойства карточки).

## Контекст

Alias учебной заметки (`type: learn-note`) был голой темой — `"Хеш-таблицы"`, `"JSON"`. Alias — то, чем Obsidian кормит автодополнение и резолвит `[[…]]`. Голый конспект (literature note, сырой захват лекции) захватывал namespace темы наравне с реальной evergreen-заметкой: `[[Хеш-таблицы]]` мог подцепить конспект вместо постоянной заметки.

Ретроспектива вскрыла: реально голых заметок — единицы; остальные органически обросли суффиксом-источником, но в **нескольких несовместимых формах** (`— «Книга»`, `(Имя курса)`, плюс кривые с дублем или вложенностью). Единой конвенции не было.

Нужно: (1) вывести alias конспекта из «голого» namespace темы; (2) по alias явно читать источник — **род** (курс / книга / …) и **провайдера**, а не гадать «это ссылка на источник или случайная ремарка».

## Решение

**Формат alias learn-note:**

```
<Тема> (<эмодзи-род> <short> @<provider> · <R-id>)
```

- `@provider` и `· <R-id>` **опускаются при отсутствии** (у книг обычно нет провайдера; у незарегистрированного источника нет R-id).
- Примеры (синтетические): `Хеш-таблицы (📖 Алгоритмы · R-001)` · `Сетевые политики (🎓 K8s-курс @<provider> · R-002)` · `Структура vault (🛠️ Руководство · R-003)`.

**Эмодзи-род** — выводится из свойства `type` карточки-источника (**НЕ из папки**: ФС — организация, не источник истины; `type` переносим с файлом, INV-1). Фиксированная карта:

| `type` | Род | Эмодзи |
|--------|-----|--------|
| `course` | курс | 🎓 |
| `book` | книга | 📖 |
| `guide` | руководство | 🛠️ |
| `source` | источник | 🌐 |

Папка врёт про суть → чинится сам `type`, а не эмодзи-исключение: если источник заведён как `type: source`, а по сути это курс, исправляется на `type: course` (и карточка перекладывается в `2-courses` для консистентности филинга с сиблингами).

**Данные — в карточке-источнике, не в alias.** В frontmatter карточки (`20-library/resources/**`) добавляются два свойства:

```yaml
short: K8s-курс         # короткое имя для суффикса alias (обязательно)
provider: <provider>    # провайдер; опционально — нет → @provider опускается
```

Шаблон learn-note (Templater) читает `short` / `provider` / род / `id` из активной карточки и собирает alias **детерминированно** — без парсинга alias, без хардкода source→label в шаблоне. R-id уже есть в `id`.

**Правила короткого имени (`short`):** ≤ ~20 символов; снять вендор-суффикс и кавычки (`K8s-курс (<provider>)` → `short: K8s-курс`, вендор уходит в `provider`); узнаваемо с одного взгляда; латиница и устоявшийся термин как есть (`K8s`).

**Машинный ключ R-id** дополнительно остаётся в имени файла (`rNNN-NN`) и инлайне `[Источник:: [[R-NNN-…]]]` — dataview и grep по источнику не зависят от alias.

**Разовый ретрофит** существующих заметок к формату (dry-run на ревью владельца → применение).

## Альтернативы

Профиль ЭМОГССБ (АрхГейт, критические — Эволюционируемость + Генеративность):

| χ | V2 имя-в-alias | **V1 frontmatter (принят)** | V3 R-id-голый |
|---|---|---|---|
| Эволюц. ⭐ | ⚠️ имя-дубль + хардкод-карта в шаблоне | ✅ данные в карточке, схема аддитивна | ✅ |
| Генерат. ⭐ | ⚠️ шаблон хардкодит source→label | ✅ native, data-driven | ✅ |
| Обучаем. | ✅ | ✅ самообъясняющий alias | ⚠️ криптично, надо знать R-id |

- **V2** (читаемое имя зашито в alias, без свойств) — отклонён: дублирует имя в каждой заметке и хардкодит карту source→label в шаблоне → проваливает оба критических.
- **V3** (голый `(R-002)`) — отклонён: криптично (Обучаемость ⚠️), а R-id для человека избыточен — он уже в имени файла и инлайне.
- **V1** (принят): 7×✅, оба критических ✅, ноль ⚠️ → прошёл вето-фильтр. Данные в frontmatter — то, что держит Э и Г зелёными.

Смежные оси, решённые по ходу: суффикс (не префикс — тема ведёт); эмодзи-род (не слово — компактно + мгновенный сигнал «источник»); `@provider` (не `·`-разделитель — не сливается).

## Последствия

- **+** Namespace разведён: конспект больше не конкурирует с evergreen на ту же тему.
- **+** Alias самодостаточен для человека (род + имя + провайдер с одного взгляда); данные — в одном владельце (карточка), не дублируются (INV-3, зеркалит ADR-0020).
- **+** Шаблон детерминирован и native-first (frontmatter + Templater + aliases, INV-18); добавить источник = завести `short` / `provider`, шаблон не трогать.
- **−** Разовый ретрофит существующих заметок (engineer-writer, INV-19) — риск мис-парса темы при снятии старого суффикса → **митигация:** dry-run «файл → старый alias → новый» на ревью владельца + откат через git. В свежем vault ретрофита нет.
- **−** Alias денормализует данные карточки (имя и провайдер копируются в заметку при создании) → при переименовании источника старые alias не пересобираются сами → перегнать ретрофит-скриптом (дёшево, обратимо).
- **−** Бэкфилл `short` / `provider` в существующие карточки-источники — предусловие ретрофита (иначе шаблону и скрипту нечего читать).
